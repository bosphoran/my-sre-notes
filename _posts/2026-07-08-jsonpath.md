## Introduction

**JSONPath** is a syntax for selecting parts of a JSON document.

In K8s, **kubectl** supports **JSONPath** expressions to extract precise fields from resource objects instead of printing full YAML/JSON.

When you use **kubectl** to interact with **K8s** (e.g., listing pods or creating deployments), K8s handles the data in JSON format behind the scenes.

When you issue a command like **kubectl apply** or **kubectl get**, kubectl communicates with the **API server**, which exposes various **HTTP endpoints**. These endpoints accept requests with a **JSON payload** (for actions like creating or updating resources) and respond with **JSON data** (such as when retrieving the current state of resources).

> **Why do we use YAML then?** YAML is more human-friendly compared to JSON. It's easier to write and read, especially for complex manifests, because it doesn't require curly braces {}, quotes "", or commas , that JSON does.

When you submit a YAML manifest using kubectl (e.g., **kubectl apply -f my-deployment.yaml**), kubectl parses the YAML, converts it to **JSON**, and then sends that **JSON data** to the **API server**.

### Creating Pod Using JSON

You can create a Pod using **JSON manifests** in exactly the same way you do with **YAML**.

```bash
# nginx.json
{
  "apiVersion": "v1",
  "kind": "Pod",
  "metadata": {
    "name": "web",
    "labels": {
      "app": "nginx"
    }
  },
  "spec": {
    "containers": [
      {
        "name": "nginx-container",
        "image": "nginx:latest",
        "ports": [
          {
            "containerPort": 80
          }
        ]
      }
    ]
  }
}
```

Now, apply it using kubectl.

```bash
vagrant@controlplane:~$ kubectl apply -f nginx.json

```

### What is JSONPath?

**JSONPath** is a query language for JSON (similar to how XPath is for XML) that allows you to extract specific information from JSON documents.

In real-world projects, there are many situations where you need to filter or retrieve specific details about a K8s object. In K8s, **kubectl** has strong integration with the **JsonPath query language**, which allows you to **filter** and extract only the information you need from K8s objects.

### Understanding JSONPath

To understand **JSONPath** better, let's create a multi-container deployment and get the details about the deployment in JSON format to understand how the output data is structured.

Create **jsonpath.yaml** with the following YAML contents.

```bash
apiVersion: apps/v1
kind: Deployment
metadata:
  name: webserver
  labels:
    app: nginx
    env: production
spec:
  replicas: 2
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx
        ports:
        - containerPort: 80
      - name: sidecar
        image: busybox
        command: ["/bin/sh", "-c", "while true; do sleep infinity; done"]
```

Create the deployment and ensure it is running.

```bash
vagrant@controlplane:~$ kubectl apply -f jsonpath.yaml
deployment.apps/webserver created

# Verify deployment
vagrant@controlplane:~$ kubectl get deploy
NAME                            READY   UP-TO-DATE   AVAILABLE   AGE
webserver                       2/2     2            2           18s
```

Each node in the tree represents a key-value pair or an element. Nodes can either contain data (like strings, numbers, booleans, etc.) or point to other nodes (like nested objects or arrays) that contain more data.

- **Root node:** The top-level element (apiVersion, Kind)
- **Intermediate nodes:** These are nodes that point to other nodes. For example, the "metadata" points to other nodes (like "annotations", "labels", etc.) that contain more data and nested values
- **Leaf nodes** are the endpoints of the tree, where the actual data is stored (e.g., strings, numbers).

### JSON Data Types

To correctly define a **jsonpath expression** for accessing the specific information, you should understand the structure and data types in a JSON document.

- **String:** Used for textual data, including words, sentences, dates, etc.
  - "apiVersion": "apps/v1",
  - "kind": "Deployment",
  - "creationTimestamp": "2024-10-27T13:34:22Z",
- **Number:** Can be integers or floating-point (decimals).
  - "generation": 1,
  - "replicas": 2,
  - "progressDeadlineSeconds": 600,
  - "revisionHistoryLimit": 10
- **Array:** It is an ordered list of values, enclosed in square brackets [].
  - The values within an array can be of different data types, such as strings, numbers, booleans, or even other arrays.
  - In the image below, "containers" is an array of two objects.

![JSON Array]({{ site.baseurl }}/assets/img/k8s-course/json-array.png)

- **Object:** Collections of **key-value pairs**, enclosed in curly braces {}.
  - The keys are strings, and the values can be any valid JSON type (string, number, Boolean, array, or another object). 
  - In the following image, **"metadata"** and **"strategy"** are both objects. They contain other **key-value pairs**, such as **"name"**, **"namespace"**, **"labels"**, and **"rollingUpdate"**.

### Querying Data with JSONPath

The basic format for using **JSONPath** with **kubectl**.

```bash
kubectl get <resource> <name> -o jsonpath='<jsonpath-expression>'
```

Now we will look at how to access different field from the output.

```bash
# Let’s start by getting the name of the Deployment.
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.metadata.name} {"\n"}'
webserver

# 
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.metadata.creationTimestamp} {"\n"}'
2026-07-08T02:10:08Z

# 
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.metadata.namespace} {"\n"}'
default

# 
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.metadata.uid} {"\n"}'
8faf019e-033f-4caf-8166-ad0fc3c9ba64

# 
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.metadata.labels} {"\n"}'
{"app":"nginx","env":"production"}
```

> When you run JSONPath, you might get the output on the same line as the command prompt. To get the JSONPath output on a new line, you need to add the **\n** newline character before the closing quote. For example: **jsonpath='{.metadata.name} {"\n"}'**

- **metadata** is a top-level key in the JSON.
- **name** is a field inside metadata.
- The **{}** is used to indicate the output format.
- The **.** means starting from the root of the JSON.

![JSON Query]({{ site.baseurl }}/assets/img/k8s-course/json-query.png)

Let’s access the key env inside the **nested field** label.

```bash
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.metadata.labels.env} {"\n"}'
production
```

> A key point to remember is that when accessing **nested fields** in a JSON object, the **dot (.) operator** allows us to move through each level of the object.

```bash
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.metadata.labels.env} {"\n"}'
production
```

The **containers** field in the JSON output is a list.

In our example, we deployed a pod with two containers, so the list contains details about both containers.

To access information about a specific container, you need to specify the index of the container in the list using square brackets **[ ]**. For example, **[0]** refers to the first container, and **[1]** refers to the second container.

```bash
# get the name of the first container
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.spec.template.spec.containers[0].name} {"\n"}'
nginx

# get the name of the second container
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.spec.template.spec.containers[1].name} {"\n"}'
sidecar

# get the names of all containers
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.spec.template.spec.containers[*].name} {"\n"}'
nginx sidecar

#
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{range.spec.template.spec.containers[*]}{.name}{"\n"}{end}'
nginx
sidecar
```

We are traversing **.spec.template.spec.containers[0].name** to get the container name.

```text
.spec
 └── .template
      └── .spec
           └── .containers
                ├── [0]   (First container in the list)
                │    └── .name  (nginx)
                └── [1]   (Second container in the list)
                     └── .name  (sidecar)
```

### Filtering

**Filtering** is primarily used to create dynamic queries that selectively retrieve data from JSON structures based on specific conditions.

Let’s say you want to find the **command** used by the container named **sidecar**. In this case, you can use the filter expression **?()**.

```bash
vagrant@controlplane:~$ kubectl get deploy webserver -o jsonpath='{.spec.template.spec.containers[?(@.name=="sidecar")].command} {"\n"}'
["/bin/sh","-c","while true; do sleep infinity; done"]
```

Lets understand **?(@.name=="sidecar")**

- **?()** is the filter operator.
- **@** refers to the current element being processed within the list (in our case, each container in the .containers list).
- **.name=="sidecar"** is the condition inside the filter. It checks if the name field of the current container equals "sidecar".

**Items:**

Now, let’s understand how to use **JSONPath** when you want to filter output for multiple objects.

For example, let’s say you want to list all the pods and retrieve the IP addresses of the containers running in those pods.

```bash
vagrant@controlplane:~$ kubectl get pods -o json
{
    "apiVersion": "v1",
    "items": [
        {
            "apiVersion": "v1",
            "kind": "Pod",
            "metadata": {
                "annotations": {
                    "cni.projectcalico.org/containerID": "7365ba11c2127fe1650b0e87617f75638a2beb8e6b97f5e20489ba8cba6b4eb4",
                    "cni.projectcalico.org/podIP": "10.244.140.69/32",
                    "cni.projectcalico.org/podIPs": "10.244.140.69/32"
                },
                "creationTimestamp": "2026-07-07T08:44:05Z",
                "generateName": "api-server-6c58d4dc65-",
                "generation": 1,
                "labels": {
                    "app": "api-server",
                    "pod-template-hash": "6c58d4dc65"
                },
# ...
# ...
```

If you check the beginning of the output, you will see **items**.

Items refers to the array containing all the pod objects returned by the **kubectl get pods** command. 
This would also apply if you tried to list **nodes**, **deployments**, **services**, etc.

Now, using **items**, let’s list all the **IP addresses** associated with the two pods.

```tex
vagrant@controlplane:~$ kubectl get pods -o jsonpath='{.items[*].status.podIP} {"\n"}'
10.244.140.69 10.244.196.190 10.244.196.191 10.244.140.65 10.244.140.71 10.244.196.129 10.244.140.67 
10.244.196.134 10.244.140.116 10.244.196.132
```

- The **[*]** is a wildcard that means "**select all elements**" in the items array..
- **.status.podIP:** This part refers to the **status.podIP** field of each pod, which holds the IP address assigned to the pod.

### Scenario 01

- List all nodes in the Kubernetes cluster.
- Extract the following details for each node:
  - Node name
  - CPU capacity
  - Memory capacity
- Use **JSONPath** to format the output and save the result into a file called **node_resources.txt**.
- The output should display **one line per node** in the following format:
  - <node_name> <cpu_capacity> <memory_capacity>

```bash
# First, list all the nodes in the cluster to see the node names:
vagrant@controlplane:~$ kubectl get nodes
NAME           STATUS   ROLES           AGE   VERSION
controlplane   Ready    control-plane   34d   v1.34.8
node01         Ready    worker          34d   v1.34.8
node02         Ready    worker          34d   v1.34.8

# Now, use JSONPath to extract the node name, CPU capacity, and the memory capacity for each node.
vagrant@controlplane:~$ kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name} {.status.capacity.cpu} {.status.capacity.memory}{"\n"}{end}'
controlplane 2 2010980Ki
node01 1 2011240Ki
node02 1 2011240Ki

# Save the output into a file called node_resources.txt
vagrant@controlplane:~$ kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name} {.status.capacity.cpu} {.status.capacity.memory}{"\n"}{end}' > node_resources.txt
```
